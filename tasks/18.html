Теория

Что нужно знать

Задание 18 — это задача оптимизации на таблице: поле-лабиринт, в каждой клетке число, исполнитель идёт по разрешённым командам и собирает числа. В 2027 году задание относится к разделу «Информационные технологии», стоит 1 первичный балл, а ответ — два целых числа.

Минимум для задания 18

  • находить стартовую и конечную клетки
  • различать внешние и внутренние стены
  • определять конечные (угловые) клетки
  • выписывать разрешённые команды и смещения
  • задавать стартовое значение динамики
  • учитывать стены при переходе
  • считать максимум и минимум отдельно
  • собирать ответ по всем конечным клеткам
  • заменять вес клетки при изменённых правилах
  • проверять порядок двух чисел в ответе

Поле, старт и финиш

Поле — квадрат N×N (в некоторых вариантах прямоугольная таблица; обычно N от 10 до 30). В каждой клетке записано число: монета, бонус, плата, высота или заряд. Исполнитель за один ход перемещается по командам условия. Число посещённой клетки добавляется к счёту; стартовая и конечная клетки тоже учитываются, если в условии не сказано иначе.

  • Старт может быть в любом углу, а не только в левом верхнем.
  • Финиш может быть один (правый нижний угол) или несколько «угловых» клеток.
  • Путь монотонный: назад и по кругу обычно ходить нельзя.
  • Числа могут быть отрицательными — тогда «максимум» и «минимум» особенно важно не перепутать.
  • Если в условии сказано «из любой левой клетки», стартов несколько.

Стены и запрещённые клетки

Стена — это утолщённая линия между клетками или по границе поля. Переход через неё запрещён. Иногда запрет задан не линией, а цветом клетки, значением 0 или диапазоном 101–499.

  • Проверяйте стену со стороны той клетки, из которой идёт ход.
  • Внешняя граница тоже стена: за пределы поля выходить нельзя.
  • Стена справа от (i, j) запрещает переход (i, j) → (i, j+1).
  • Стена снизу от (i, j) запрещает переход (i, j) → (i+1, j).
  • Запрещённую клетку удобно считать недостижимой: dp = None или −∞/+∞.

Динамика по клеткам

Главная идея: лучший результат в клетке зависит только от лучших результатов в клетках, из которых в неё можно прийти. Для команд «вправо» и «вниз» это верхний и левый соседи. Для минимума нужна отдельная копия таблицы: значения максимума не равны значениям минимума, поэтому таблицу нужно пересчитать с MIN.

  • Если сверху стена, верхний сосед не рассматривается.
  • Если слева стена, левый сосед не рассматривается.
  • Если оба перехода запрещены, клетка недостижима.
  • Для минимума нельзя инициализировать нулём: ноль может оказаться «лучше» реального пути.
dp_max[i][j] = a[i][j] + max(dp_max[i-1][j], dp_max[i][j-1])dp_min[i][j] = a[i][j] + min(dp_min[i-1][j], dp_min[i][j-1])dp[0][0] = a[0][0]недостижимо: −∞ для максимума, +∞ для минимума

Порядок обхода

Формулы работают, только если к моменту обработки клетки все её предшественники уже посчитаны. Порядок зависит от команд.

  • «вправо/вниз»: строки сверху вниз, внутри строки слева направо.
  • «влево/вниз»: строки сверху вниз, внутри строки справа налево.
  • «вверх/вправо»: строки снизу вверх, внутри строки слева направо.
  • «вверх/влево»: строки снизу вверх, внутри строки справа налево.
  • Если направлений несколько, ориентируйтесь на то, что все предшественники должны быть раньше.
«влево/вниз»: dp[i][j] = a[i][j] + max(dp[i][j+1], dp[i-1][j])«вверх/вправо»: dp[i][j] = a[i][j] + max(dp[i+1][j], dp[i][j-1])«вверх/влево»: dp[i][j] = a[i][j] + max(dp[i+1][j], dp[i][j+1])

Конечные клетки

В формулировке «угловые клетки, справа и снизу ограниченные стенами» финишей может быть несколько. Это не только правый нижний угол: любая клетка, из которой нельзя пойти вправо и вниз, даёт итоговую сумму.

  • Сначала отметьте все такие клетки, затем считайте динамику по всему полю.
  • Максимум и минимум берите по значениям во всех конечных клетках.
  • Если в условии прямо сказано «в правую нижнюю клетку», финиш один.
  • Для «Коня» или «Попрыгуна» конечная клетка — та, из которой нет ни одного разрешённого хода.
  • Не отбрасывайте конечную клетку только потому, что она не в правом нижнем углу.

Максимум и минимум

Это две независимые задачи. Их удобно решать на двух копиях листа или двумя массивами в программе.

  • Сначала заполните таблицу для максимума, сохраните ответ.
  • Затем сделайте копию и замените МАКС на МИН (или max на min).
  • Не меняйте функцию в уже заполненной таблице без копии — потеряете максимум.
  • Для минимума проверяйте, что путь вообще существует.
  • В ответе сначала то число, которое просят первым: часто «максимум, затем минимум», но бывает и наоборот.

Изменённые правила сбора

В основе почти всех вариантов — та же динамика. Меняется только вес клетки или условие перехода.

  • Удвоенный номинал: w = 2·a[i][j].
  • Чётное — удвоить, нечётное — половина: w = 2x при x % 2 == 0, иначе x // 2.
  • Произведение номинала на число вхождений: w = x · count(x).
  • Энергия: старт — a[0][0], шаг вправо вычитает число целевой клетки, шаг вниз — ceil(число целевой клетки / 2).
  • Обязательная клетка: считайте путь старт → клетка и клетка → финиш отдельно.
  • Заправки: храните в динамике запас энергии, а не только сумму.
  • Шаг зависит от числа в текущей клетке: для каждого состояния перебирайте только разрешённые смещения (№ 29454).

Excel или программа

Оба способа допустимы. В Excel удобно видеть разметку стен, в программе — автоматически обрабатывать сложные правила и проверять себя.

  • Excel: формулы МАКС/МИН, относительные ссылки, заливка клеток по типу перехода.
  • Excel: для стен вручную уберите запрещённого соседа из формулы.
  • Python: openpyxl для .xlsx, pandas.read_excel(..., engine='odf') для .ods.
  • Python: стены читайте из cell.border или задавайте матрицей запретов.
  • Проверка: пройдите найденный маршрут вручную и сложите числа.

Формат ответа

Ответ — два целых числа. В задании 18 почти всегда просят пару «максимум и минимум», но порядок задаётся условием.

  • Записывайте числа через пробел, без единиц и пояснений.
  • Если просят «сначала минимальную, затем максимальную» — не переставляйте.
  • Если в ответе одно число (например, количество маршрутов), не добавляйте второе.
  • Проверьте, что оба числа целые и не содержат разделителей тысяч.

02

когда нужны стены и несколько финишей

Динамика в Python

Когда использовать: Поле большое, стены заданы границами ячеек, конечных клеток несколько, нужна автоматическая проверка.

  1. Прочитайте числа: openpyxl для .xlsx, pandas.read_excel(..., engine='odf') для .ods.
  2. Соберите матрицу чисел a и матрицы запретов: right_wall, down_wall или blocked.
  3. Заведите таблицу dp размера N×N; старт dp[0][0] = a[0][0].
  4. Обходите клетки в порядке движения; для каждой собирайте только допустимых предшественников.
  5. Для максимума берите max(prev), для минимума — min(prev); если предшественников нет, клетка недостижима.
  6. Соберите значения в конечных клетках и выведите ответ в нужном порядке.

Пример

Поле из учебного примера: стены справа и снизу от (0,2), конечные клетки — (0,2) и (3,3).

a = [[2, 5, 1, 9],
     [4, 8, 7, 2],
     [1, 3, 9, 5],
     [7, 2, 6, 8]]

right_wall = {(0, 2)}   # стена справа от клетки (0, 2)
down_wall = {(0, 2)}    # стена снизу от клетки (0, 2)
finals = [(0, 2), (3, 3)]

def best(maximize=True):
    n = len(a)
    dp = [[None] * n for _ in range(n)]
    dp[0][0] = a[0][0]
    for i in range(n):
        for j in range(n):
            if i == 0 and j == 0:
                continue
            prev = []
            if j > 0 and (i, j - 1) not in right_wall and dp[i][j - 1] is not None:
                prev.append(dp[i][j - 1])
            if i > 0 and (i - 1, j) not in down_wall and dp[i - 1][j] is not None:
                prev.append(dp[i - 1][j])
            if prev:
                dp[i][j] = a[i][j] + (max(prev) if maximize else min(prev))
    values = [dp[i][j] for i, j in finals if dp[i][j] is not None]
    return max(values) if maximize else min(values)

print(best(True), best(False))  # 45 8

04

диагональ, прыжок, ход на две клетки

Три и более команд

Когда использовать: Разрешены диагональ, прыжок коня, ход на две клетки или команда зависит от клетки.

  1. Выпишите все команды и смещения: (0,1), (1,0), (1,1), прыжок коня и т. п.
  2. Для клетки переберите все команды; предшественник — клетка минус смещение.
  3. Проверьте, что предшественник внутри поля и переход не перекрыт стеной.
  4. Если команда разрешена только из части клеток, добавьте условие на предшественника.
  5. Обходите клетки так, чтобы предшественники были готовы.
  6. Для «жёлтых» клеток, где разрешена только диагональ, формулы меняются по цвету клетки.

Пример

05

когда просят не сумму, а число путей

Количество маршрутов

Когда использовать: В условии «количество различных маршрутов», «сколько способов», а не максимум и минимум.

  1. В стартовой клетке поставьте 1.
  2. В каждой клетке сложите числа путей из разрешённых предшественников.
  3. Стена или запрещённая клетка просто не добавляет путей.
  4. Если стартов несколько, поставьте 1 в каждой; если финишей несколько, сложите ответы.
  5. Проверьте, что путь не проходит через запрещённые клетки.

Пример

Поле 3×3 без стен, движение «вправо/вниз», старт (1,1), финиш (3,3).

dp[0][0] = 1

for i in range(n):
    for j in range(n):
        if i:
            dp[i][j] += dp[i - 1][j]
        if j:
            dp[i][j] += dp[i][j - 1]

06

удвоение, половина, произведение, энергия

Изменённые правила сбора

Когда использовать: Сумма считается не как «число клетки», а по особому правилу; или есть обязательная клетка и заправки.

  1. Выпишите вес клетки w(i,j) по правилу условия.
  2. Подставьте w вместо a в рекуррентную формулу.
  3. Если вес зависит от направления входа, добавьте его в конкретный переход.
  4. Для обязательной клетки считайте два участка и вычтите её число один раз.
  5. Для энергии храните в динамике запас, а не сумму; проверяйте, что ход возможен.
  6. Проверьте, что стартовая клетка обрабатывается по тому же правилу, если условие не делает исключения.

Пример

Поле 2×2: 1 2 / 3 4. Каждая посещённая клетка удваивается, включая старт.

# максимальный путь 1 -> 3 -> 4: 2 + 6 + 8 = 16
# минимальный путь 1 -> 2 -> 4: 2 + 4 + 8 = 14

Ответ16 14.

По мотивам задач № 17983, 3371, 22499, 3896 и 832.

07

несколько таблиц и особые ходы

Нестандартные поля и два исполнителя

Когда использовать: Полей несколько, числа стоят не во всех клетках, ходы нестандартные.

  • «Попрыгун»: числа только в части клеток; постройте граф «ближайшее число справа/снизу» и считайте динамику по числам (№ 17098).
  • Два исполнителя: считайте две независимые таблицы и сравнивайте результаты (№ 470, 14314).
  • «Ладья»: ход на любое расстояние вправо/вниз; перебирайте всю строку и столбец или поддерживайте лучший префикс (№ 2162).
  • «Змейка»: в нечётных строках движение вправо/вниз, в чётных — влево/вниз (№ 583).
  • «Переход через поле»: старт — любая клетка первой строки/столбца, финиш — любой клетки последней; добавьте фиктивный старт и финиш (№ 1757, 2126).
  • Заблокированные цветом клетки (голубые, серые) считайте стенами (№ 2527, 726).

Пример

Поле 2×2: 1 2 / 3 4. Исполнитель A идёт из левого верхнего угла вправо/вниз, исполнитель B — из левого нижнего вверх/вправо.

ОтветУ A максимум 8 (1→3→4), у B максимум 9 (3→4→2). Побеждает B с результатом 9.

По мотивам задач № 17098, 470, 2162, 583, 1757 и 2527.

Типичные ошибки

  • не учтена стена
  • потеряна конечная клетка
  • минимум считается по таблице максимума
  • не учтены старт или финиш
  • перепутан порядок чисел

Ключевые формулы

  • dp_max[i][j] = a[i][j] + max(dp_max сверху, dp_max слева)
  • dp_min[i][j] = a[i][j] + min(dp_min сверху, dp_min слева)
  • старт: dp[0][0] = a[0][0]
  • ответ: max/min по всем конечным клеткам
