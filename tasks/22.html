Что проверяет

Анализ совокупности параллельных и последовательных процессов: зависимости, время старта и окончания, критический путь, одновременность выполнения и ограничения на число ядер.

Основание: проект спецификации и кодификатора КИМ 2027. Открыть документы ↗

Теория

Что нужно знать

Задание 22 — это задача о расписании. По таблице процессов нужно понять, какие из них можно запускать одновременно, а какие обязаны ждать. Почти весь ответ считается через две величины: ранний старт и раннее окончание процесса. Дальше вопрос лишь в том, что именно просят: общее время, число одновременно работающих процессов, длительность перекрытия или неизвестную длительность.

Минимум для задания 22

  • читать таблицу процессов и разделитель «;»
  • отличать независимый процесс (0) от зависимого
  • строить граф зависимостей
  • находить ранний старт и раннее окончание
  • видеть критический путь и запас времени
  • строить диаграмму Ганта
  • считать процессы на отрезке и в конкретную миллисекунду
  • различать «ровно k» и «не более k»
  • решать обратные задачи с неизвестным t
  • проверять единицы измерения и границы интервалов

Таблица процессов

В файле обычно три столбца: ID процесса, время его выполнения и ID процессов, от которых он зависит. Значение 0 означает, что процесс независим и может стартовать в момент 0. Один и тот же процесс может быть зависимым для нескольких других.

  • ID — это метка, а не номер очереди: порядок строк в файле не обязан совпадать с порядком выполнения.
  • Время может быть в миллисекундах, минутах или днях — единицы берите из вопроса.
  • Зависимости перечислены через «;»; несколько ID в одной ячейке означают несколько зависимостей.
  • Если зависимостей несколько, уточните по условию: ждать нужно все или хотя бы одну.
  • Значение 0 в столбце зависимостей — не отдельный процесс, а пометка независимости.
B зависит от A → B нельзя начинать раньше окончания A0 → независимый процесс, старт с момента 0

Граф зависимостей

Таблицу удобно превратить в ориентированный граф: вершина — процесс, стрелка A → B — зависимость. В корректной таблице циклов нет, иначе выполнение невозможно. Независимые процессы — вершины без входящих стрелок; они могут идти параллельно.

  • Источники графа (нет зависимостей) стартуют в момент 0.
  • Стоки (от них никто не зависит) определяют возможные окончания.
  • Параллельные ветви не складываются: общее время задаёт самая длинная ветвь.
  • Если в графе получился цикл, проверьте чтение таблицы — в задании такого быть не должно.
  • На черновике удобно нарисовать граф и подписать рядом длительности.
путь = последовательность A → B → …время пути = сумма длительностей вершин

Ранний старт и раннее окончание

Главная формула задания. Для процесса B старт — это максимум окончаний всех его зависимостей, а окончание — старт плюс собственная длительность. Считаем в топологическом порядке: сначала процессы без зависимостей, затем те, у которых зависимости уже посчитаны.

  • start(B) = 0, если зависимостей нет.
  • finish(B) = start(B) + t(B).
  • По умолчанию процесс стартует в самый ранний допустимый момент; лишних задержек не добавляем.
  • Для нескольких зависимостей берём максимум окончаний, а не сумму.
  • Если сказано «хотя бы один из A», берём минимум, а не максимум.
  • Общее минимальное время — максимум finish по всем процессам.
start(B) = max(finish(A₁), …, finish(Aₖ))finish(B) = start(B) + t(B)T = max finish(B)

Критический путь и запас времени

Критический путь — самая длинная по суммарной длительности цепочка от независимого процесса до последнего. Именно она задаёт минимальное общее время: сколько ни распараллеливай остальные ветви, короче критического пути не получится.

  • Длина критического пути равна минимальному времени выполнения всей совокупности.
  • Процесс на критическом пути не имеет запаса: его задержка сразу увеличивает ответ.
  • У процесса вне критического пути есть резерв: он может подождать без роста общего времени.
  • Критических путей может быть несколько; тогда запас равен нулю у всех процессов на них.
  • Для вопроса «время не зависит от t» проверяйте, лежит ли этот процесс на всех критических путях.
T = длина критического путиslack(B) = late_start(B) − start(B)критический путь: slack = 0

Диаграмма Ганта

Диаграмма Ганта — это полоски процессов на оси времени. Она превращает таблицу в картинку: видно, где процессы перекрываются, где образуются «окна» и сколько процессов работает в каждый момент.

  • По горизонтали — время, по вертикали — процессы; длина полоски равна t(B).
  • Полоска начинается в start(B) и заканчивается в finish(B).
  • Зависимость означает, что полоска B не может начаться левее конца A.
  • Полоски на разных строках с общим участком — это параллельная работа.
  • Диаграмму удобно рисовать в масштабе: 1 клетка = 1 мс, 5 мс или 10 мс.
полоска B: [start(B), finish(B))длина полоски = finish(B) − start(B) = t(B)

Как считать одновременность

Вопросы про «сколько процессов одновременно» решаются по диаграмме Ганта. Нужно разбить время на отрезки между соседними стартами и финишами: внутри такого отрезка набор активных процессов не меняется.

  • Процесс активен на [a, b), если start ≤ a < finish.
  • В момент finish процесс уже освободил ресурс, а в момент start — только занял.
  • Если один процесс закончился в 5 мс, а другой начался в 5 мс, одновременно они не выполнялись.
  • Для суммарной длительности «ровно k» складывайте длины всех таких отрезков.
  • Для максимальной продолжительности ищите самый длинный непрерывный участок; соседние отрезки с одинаковым счётчиком объединяются.
  • Для «хотя бы k» учитывайте отрезки, где активны k и более процессов.
  • Для «на m-й мс» при нумерации с 1 проверяйте start < m ≤ finish.
active(p, a) = start(p) ≤ a < finish(p)длительность отрезка = b − am-я мс: start < m ≤ finish

Ограничение на число одновременных процессов

Иногда сказано, что ядер, потоков или разрешений хватает только на k одновременных процессов. Тогда задача превращается в расписание на k «станках»: зависимости по-прежнему нельзя нарушать, а в каждый момент работает не больше k процессов.

  • Сначала найдите критический путь L и суммарную длительность S.
  • Нижняя граница: T ≥ max(L, ⌈S / k⌉).
  • Если пауза разрешена, процесс можно прервать и продолжить на другом ядре.
  • Если пауза запрещена, процесс занимает ядро целиком от старта до финиша.
  • При запрете паузы нижняя граница не всегда достигается: нужна проверка диаграммой.
  • При равных приоритетах сначала запускайте процесс с более длинным «хвостом» до конца.
T ≥ max(L, ceil(S / k))S = сумма t(B)L = длина критического пути

Неизвестное время t

В обратных задачах один процесс имеет неизвестную длительность t. Все окончания зависят от t монотонно: больше t — не меньше время. Поэтому подходящее t ищут перебором, двоичным поиском или решением неравенства для критического пути.

  • Подставьте t в формулы start/finish и определите, на какие пути он влияет.
  • Если t лежит на критическом пути, общее время обычно равно const + t.
  • Если t не на критическом пути, небольшое изменение t может не менять ответ.
  • Для «уложиться не более чем за T» ищите максимальное t с total(t) ≤ T.
  • Для «минимальное время не зависит от t» ищите диапазон, где запас процесса положителен.
  • Проверяйте граничные значения t и целочисленность ответа.
total(t) — неубывающая функцияtotal(t) ≤ T → t ≤ t_maxесли t вне критического пути, total(t) = const

Разновидности формулировок

Одна и та же таблица может спрашивать о разном. Перед расчётом выпишите, что именно нужно найти, и только потом считайте.

  • «Минимальное время завершения» — максимум finish.
  • «Максимальная продолжительность одновременного выполнения k процессов» — самый длинный отрезок с ровно k активными.
  • «Максимальное количество процессов одновременно» — максимум счётчика; длительность нужна только если её спросили отдельно.
  • «Сколько процессов завершится за первые N мс» — считайте finish ≤ N, если не сказано иначе.
  • «Сколько процессов завершится за последние N мс» — считайте finish > T − N.
  • «На m-й мс» — активные на эту миллисекунду, с учётом нумерации.
  • «ID процесса, начавшегося последним» — максимум start; при равенстве смотрите порядок в условии.
  • «Разница двух режимов или проектов» — посчитайте два ответа и вычтите.
  • «Неизвестное t» — решайте обратную задачу, а не прямой расчёт.
  • «Проценты зависимостей» — берите k-е окончание, а не максимум.
вопрос → величина → формулане считайте лишние величины: ответ — одно число

Проверка ответа

Ответ в задании 22 — целое число. Почти все ошибки связаны не с арифметикой, а с границами и единицами. Поэтому последние минуты потратьте на проверку диаграммы и критического пути.

  • Проверьте, что длина критического пути совпадает с ответом для общего времени.
  • Убедитесь, что единицы ответа совпадают с вопросом: мс, минуты, дни, часы.
  • Проверьте, не сложили ли вы времена параллельных ветвей.
  • Проверьте границу: процесс, закончившийся в момент N, входит в первые N мс.
  • Для «ровно k» не подсчитайте отрезки с k + 1 процессом.
  • Для «не более k» убедитесь, что расписание действительно использует не больше k ядер.
  • Подставьте ответ обратно в таблицу и пройдите по зависимостям ещё раз.
ответ — целое число без поясненийпроверка: критический путь и диаграмма Ганта

Способы решения

Выберите метод под формулировку

Методы собраны по решениям задания 22 из базы Kompege. Начните с того, что именно нужно найти в условии.

01

мало процессов, нужен ответ без кода

Ручной расчёт по таблице

Когда использовать: В файле 8–20 процессов, зависимости простые, удобно считать по слоям от независимых процессов к последним.

  1. Отсортируйте процессы так, чтобы зависимости шли раньше зависимых.
  2. Независимым процессам (зависимость 0) поставьте старт 0.
  3. Для каждого следующего процесса старт = максимум окончаний его зависимостей.
  4. Окончание = старт + длительность процесса.
  5. Для общего времени возьмите максимум окончаний по всем процессам.
  • Промежуточные значения пишите прямо в таблицу: старт, окончание.
  • Если зависимостей несколько, максимум берётся по всем, а не по первой.
  • Для формулировки «хотя бы один из A» берите минимум окончаний.
  • Проверяйте, что все зависимости процесса уже посчитаны.

Пример

Процессы: 1 (4 мс, 0), 2 (3 мс, 0), 3 (1 мс, 1; 2), 4 (7 мс, 3).

Ответstart3 = max(4, 3) = 4, finish3 = 5; start4 = 5, finish4 = 12. Общее время — 12 мс.

По решениям № 9948, 10129, 14317.

02

много строк, данные в xlsx или ods

Excel и электронная таблица

Когда использовать: Файл открывается в Excel, процессов много, считать вручную долго, а ответ нужен быстро.

  1. Убедитесь, что ID, время и зависимости лежат в отдельных столбцах.
  2. Разделите зависимости по столбцам: Данные → Текст по столбцам, разделитель «;».
  3. Для каждой зависимости подтяните её окончание через ВПР или ИНДЕКС/ПОИСКПОЗ.
  4. Старт = МАКС подтянутых окончаний; для независимого процесса — 0.
  5. Окончание = время + старт; ответ = МАКС по столбцу окончаний.
  • Сначала создайте строку для фиктивного процесса 0 с окончанием 0.
  • Если зависимостей до четырёх, разнесите их по отдельным столбцам.
  • Формулы протягиваются вниз; следите за абсолютными ссылками на диапазон таблицы.
  • Для вопросов про одновременность постройте рядом столбцы старта и финиша.

Пример

Шаблон формул из разборов: зависимости разнесены по столбцам, окончания подтянуты, старт считается через МАКС.

=ВПР(C2; $A:$M; 11; 0)
=B2 + МАКС(G2:J2)
=МАКС(E:E)

ОтветДля учебной таблицы выше протянутые формулы дают 16 мс.

По решениям № 9948 и 10129 (С. Чайкин).

03

десятки процессов, нужен точный расчёт

Python: один проход по зависимостям

Когда использовать: В файле много строк или нужно проверить ручной ответ программой.

  1. Прочитайте строки и замените разделитель «;» на пробел.
  2. Сложите данные в словарь ID → (время, список зависимостей).
  3. Повторяйте проход, пока не посчитаны все процессы: готов тот, чьи зависимости уже посчитаны.
  4. Для готового процесса finish = максимум finish зависимостей + его время.
  5. Ответ — максимум по словарю окончаний или другая нужная величина.
  • Служебный процесс 0 сразу получает окончание 0.
  • Для «хотя бы один» замените max на min.
  • Если в файле проценты зависимостей, понадобится отдельная логика выбора k-го окончания.
  • Проверьте, что цикл завершился: иначе в таблице есть цикл или опечатка.

Пример

Файл 22.csv: ID; время; зависимости; …

data = {}
for line in open('22.csv', encoding='utf-8'):
    parts = line.strip().replace(';', ' ').split()
    if len(parts) < 3:
        continue
    pid, t, deps = parts[0], int(parts[1]), parts[2:]
    data[pid] = (t, deps)

finish = {'0': 0}
while len(finish) < len(data) + 1:
    for pid, (t, deps) in data.items():
        if pid not in finish and all(d in finish for d in deps):
            finish[pid] = max(finish[d] for d in deps) + t

print(max(finish.values()))

ОтветДля учебной таблицы выше программа напечатает 16.

По программным решениям № 11239 и 22501.

04

вопросы про одновременность

Диаграмма Ганта и события

Когда использовать: Спрашивают максимальное или ровно k процессов, длительность перекрытия, конкретную миллисекунду, «за первые N мс».

  1. Посчитайте start и finish для всех процессов.
  2. Выпишите все моменты старта и финиша и отсортируйте их.
  3. Между соседними моментами набор активных процессов не меняется.
  4. Для каждого отрезка проверьте, кто активен: start ≤ a < finish.
  5. Для максимальной продолжительности объединяйте соседние отрезки с нужным счётчиком; для суммарной — складывайте их длины.
  • Интервал полуоткрытый: в момент finish процесс уже свободен.
  • Если один закончился в 5 мс, а другой начался в 5 мс, одновременно они не работали.
  • Для «хотя бы k» учитывайте отрезки, где счётчик не меньше k.
  • Соседние отрезки с одинаковым счётчиком — один непрерывный интервал.
  • Для «на m-й мс» при нумерации с 1 проверяйте start < m ≤ finish.

Пример

Для учебной таблицы выше постройте все отрезки между моментами 0, 3, 4, 5, 11 и 16.

# finish уже посчитан, как в методе 03

05

ядра, потоки, «не более k»

Ограничение числа одновременных процессов

Когда использовать: Сказано, что одновременно можно выполнять не более k процессов, а также разрешена или запрещена приостановка.

  1. Найдите критический путь L и суммарную длительность S.
  2. Проверьте нижнюю границу T ≥ max(L, ceil(S / k)).
  3. Если пауза разрешена, распределяйте процессы по k слотам с приоритетом длинного «хвоста».
  4. Если пауза запрещена, процесс занимает слот целиком; распределяйте готовые процессы по диаграмме.
  5. Если в нижнюю границу не укладывается, увеличивайте T и ищите допустимое окно.
  • При паузе суммарная загрузка k ядер равна S, поэтому T не меньше ceil(S / k).
  • Критический путь нельзя ускорить параллелизмом.
  • Без паузы жадный выбор «сначала самый короткий» не всегда оптимален.
  • Для небольших N перебирайте варианты по диаграмме и проверяйте зависимости.
  • В каждом слоте в любой момент должно быть не больше k процессов.

Пример

Три независимых процесса длительностью 4, 3 и 5 мс, доступно k = 2 ядра.

ОтветS = 12, L = 5, нижняя граница max(5, ceil(12 / 2)) = 6. С паузой можно уложиться в 6 мс; без паузы минимальное время — 7 мс (4 + 3 на одном ядре, 5 на другом).

По задачам о ядрах и потоках № 5414, 10595, 12541, 15207.

06

параметр, «не более чем за», «не зависит»

Неизвестное время t

Когда использовать: Одно время неизвестно, нужно наибольшее или наименьшее t, при котором все процессы завершаются к сроку.

  1. Обозначьте неизвестную длительность t и подставьте её в формулы старта и финиша.
  2. Убедитесь в монотонности: при увеличении t время финиша не уменьшается.
  3. Для условия «уложиться в T» найдите границу двоичным поиском или решите неравенство.
  4. Если сказано «минимальное время не зависит от t», проверьте запас процесса.
  5. Подставьте найденное t обратно и проверьте граничные значения.
  • Для целого t двоичный поиск по диапазону 0…10⁶ делает около 20 проверок.
  • Если t входит в несколько путей, время задаёт самый длинный из них.
  • Для «не зависит» сравните длину критического пути с t и без него.
  • Ответ должен быть целым; не забудьте про единицы измерения.

Пример

Критический путь без неизвестного процесса равен 40 мс, с ним — 40 + t. Все процессы должны завершиться не более чем за 134 мс.

# data — из метода 03; unknown — ID процесса с неизвестным временем
unknown = '7'
limit = 134

def total(t):
    finish = {'0': 0}
    while len(finish) < len(data) + 1:
        for pid, (d, deps) in data.items():
            if pid not in finish and all(x in finish for x in deps):
                dur = t if pid == unknown else d
                finish[pid] = max(finish[x] for x in deps) + dur
    return max(finish.values())

lo, hi = 0, 10**6
while lo < hi:
    mid = (lo + hi + 1) // 2
    if total(mid) <= limit:
        lo = mid
    else:
        hi = mid - 1
print(lo)

Ответ40 + t ≤ 134, поэтому t ≤ 94. Наибольшее целое t — 94.
